# RBY1 고정 베이스 소금통 픽업 테스트

## 목표

`MolmoBot-RBY1Multitask` 체크포인트를 사용하여 시뮬레이션에서 RBY1 모바일
매니퓰레이터가 소금통을 성공적으로 집어 올리는 것.

## 현재 상태: 재훈련 필요

모든 추론 시점 수정이 소진됨. 물리 시뮬레이션은 검증 완료 (IK 그래스프로
6-40cm 들어올림 성공), 그러나 학습된 정책이 근본적인 작업 공간 한계로 이를
재현할 수 없음.

**근본 원인:** 정책이 토르소를 영점에 둔 채 팔만으로 조작하는 것을 학습함.
소금통은 팔만의 작업 공간 밖에 위치. 평가 시 토르소 높이를 강제 오버라이드해도
정책의 팔 궤적이 토르소=0 구성에 결합되어 있어 효과 없음.

## 실험 결과 요약

### 1단계: 그리퍼 및 씬 디버깅 (38 커밋)

씬 설정, 그리퍼 극성, 카메라 뷰, 물체/로봇 포즈 스윕, 그리퍼 타이밍 변형,
포인트 프롬프트를 체계적으로 배제함.

| 실험 | 결과 | 결론 |
|------|------|------|
| 그리퍼 극성/클램핑 | 수정됨 | 잘못된 명령 규칙 사용 중이었음 |
| 닫기 히스테리시스 (24스텝) | 개선 없음 | 그리퍼 타이밍 문제 아님 |
| 카메라 뷰 재배치 (5개 변형) | 모두 악화 | 체크포인트가 학습 시 순서에 민감 |
| 물체/로봇 포즈 스윕 (20+ 변형) | 최고 중점 7.1cm | 개선되었으나 여전히 그래스프 실패 |
| 포인트 프롬프트 / 도어 스타일 | 악화 (5cm→10cm) | 픽 태스크에 도움 안 됨 |
| 접촉 유지 / 접촉 게이트 | 그래스프 실패 | 접촉 기하학 불량 |
| 스크립트 그래스프 재생 | 그래스프 실패 | 정렬 오류 있는 웨이포인트 재생 |

**최고 결과:** TCP 7mm 이내 접근, 손가락 중점 6-7cm 측면 오프셋.

### 2단계: IK 픽 검증 (CuRobo/CUDA 불필요)

MuJoCo DLS IK로 올바른 그래스프 포즈를 계산하고, 학습된 정책을 우회하여
직접 관절 제어로 실행하여 물리 시뮬레이션이 작동함을 증명.

| 테스트 | 결과 |
|--------|------|
| IK 손가락 정렬 (독립 모델) | **0.1mm** 정확도 |
| 팔만 IK (토르소 영점 고정) | **실패** - 물체 작업공간 밖 |
| 팔만 IK (토르소 높이=0.50-0.60) | **성공** - 물체 도달 가능 |
| 평가 파이프라인 IK (PD 컨트롤러) | 중력으로 토르소 드리프트 |
| PD 게인 부스트 (10x, 100x) | 여전히 드리프트, 결합 체인 동역학 |
| 전체 씬 직접 qpos (1x 마찰) | 물체 6.8cm 밀림, 들어올림 없음 |
| 전체 씬 직접 qpos (5x 마찰) | **물체 6-40cm 들어올림 성공** |

**핵심 발견:**
- EE-손가락 끝 오프셋: 손목 Z축 방향 47mm
- 소금통 충돌체: 단일 박스 2.6x5.5x2.6cm, 기본 마찰 0.9
- 중력 보상 (`gravcomp=True`) 이미 평가 파이프라인에서 활성화
- 토르소 "height" 모드: 1D 스칼라를 6D 관절로 매핑 (h, -2h, h, 0, 0, 0)

### 3단계: 마찰 수정 정책 평가 (GPU, RTX 4080)

실제 정책으로 5x 마찰 부스트를 고정 베이스 벤치마크에서 테스트.

| 메트릭 | 마찰 수정 전 | 5x 마찰 적용 |
|--------|-------------|--------------|
| 최고 TCP 거리 | 0.0076m | 0.028m |
| 최고 중점 거리 | 0.063m | 0.073m |
| 물체 이동 | 0.0 | 0.0 |
| 성공 | 0/6 | 0/6 |

**결론:** 손가락이 물체에 도달하지 못하므로 (6-7cm 측면 오차) 마찰만으로는
효과 없음. 마찰은 작업공간 문제가 해결된 후에만 의미 있음.

### 4단계: 고정 토르소 높이 오버라이드 (GPU, RTX 4080)

정책의 영점 토르소 출력을 IK 검증된 높이 0.50으로 강제 오버라이드하여 테스트.

| 메트릭 | 토르소=0 (기본) | 토르소=0.50 (고정) |
|--------|----------------|---------------------|
| 최고 TCP 거리 | 0.028m | 0.065m (악화) |
| 최고 중점 거리 | 0.073m | 0.072m (동일) |
| 물체 이동 | 0.0 | 0.0 |
| 성공 | 0/6 | 0/6 |

**결론:** 정책의 팔 궤적은 토르소=0에 적응되어 있음. 토르소 높이를 변경하면
팔의 기준 프레임이 바뀌지만, 정책이 팔 명령을 그에 맞게 조정하지 않음.
팔 궤적과 토르소는 함께 학습되어야 함.

## 배제된 가설

| 가설 | 테스트 방법 | 결과 |
|------|-----------|------|
| 그리퍼 극성 오류 | 클램프 규칙 수정 | 문제였음, 수정 완료 |
| 그리퍼 닫기 타이밍 | 히스테리시스, 접촉 트리거 | 문제 아님 |
| 카메라 순서 오류 | 5개 뷰 어블레이션 | 현재 순서가 최적 |
| 물체 위치 부적절 | 20+ 포즈 스윕 | 약간 도움, 불충분 |
| 포인트 프롬프트 필요 | 픽에 활성화 | 오히려 악화 |
| 시뮬레이터 픽 불가 | IK + 직접 qpos | 5x 마찰로 성공 |
| 기본 마찰 부족 | 5x 마찰 부스트 | 수정됨, 정책은 여전히 미스 |
| 물체 도달 불가 | 토르소 높이 스윕 IK | h=0.50-0.60에서 도달 가능 |
| 토르소 높이만 오버라이드 | 고정 h=0.50 평가 | 정책 팔이 적응 안 함 |
| PD 컨트롤러 약함 | 게인 100x 부스트 | 결합 체인이 PD 무효화 |

## 결론

이 태스크는 현재 체크포인트가 픽 태스크에 대해 학습하지 못한 **토르소 + 팔의
협조 동작**을 요구함. 체크포인트는 토르소 이동을 포함하는 CuRobo 생성
데모로 훈련되었지만, 정책은 토르소를 영점에 유지하고 팔만의 궤적을 사용하는
것을 학습함.

## 다음 단계 (재훈련 필요)

1. **토르소 활용 픽 데모로 파인튜닝**
   - 명시적 토르소 이동이 포함된 CuRobo 픽 궤적 50-100개 생성
   - `MolmoBot-RBY1Multitask`를 새 데이터로 파인튜닝
   - 기존 훈련 데이터와 혼합하여 catastrophic forgetting 방지

2. **훈련 데이터 토르소 통계 조사**
   - CuRobo 픽 훈련 데이터에 실제로 토르소 변동이 있는지 확인
   - 훈련 데이터에서 토르소가 항상 영점 근처라면, 정책이 이를 무시하는 것이
     올바른 학습 결과

3. **1D height 대신 6D 토르소 액션 시도**
   - height 모드는 토르소를 1D 매니폴드로 제한
   - 전체 6D 관절 제어로 더 풍부한 토르소 구성 가능
   - 새로운 action spec으로 재훈련 필요
