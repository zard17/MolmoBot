# RBY1 Pick/PnP View Ablation Summary

Date: 2026-04-15

## Goal

Check whether the RBY1 Pick/PnP salt-shaker failure is caused by policy input
view selection/order, without retraining the model.

The investigation used the custom salt-shaker benchmark and one selected
episode per variant. Each variant ran a 25-step smoke test first, then a
300-step full rollout if smoke passed. The first baseline full run completed at
400 steps because the runner default still matched the earlier debug setting;
the runner default was then corrected to 300.

## Visibility Findings

Smoke analysis showed that the salt shaker is clearly present in `head_camera`
and `exo_camera_1`, while both wrist views have weak or no early object signal.
`exo_camera_1` is observation/recording only and is not passed to the policy.

## Conclusion

Camera view/order is not the primary fix path for this benchmark. The right
wrist view is consistently uninformative, but removing it or reordering views
degrades action quality. The current checkpoint appears sensitive to the
training-time camera distribution/order even when one view is visually weak.

Do not retry the failed view settings unless there is a model/config change:

```text
left_focused_head_left
left_wrist_first
left_only
left_first_full
```

The next recommended non-model work is to return to physical/action-side fixes:

1. Keep the original policy camera order for RBY1 Pick/PnP.
2. Continue with gripper timing/hysteresis and small pose/torso/table geometry
   adjustments.
3. If camera work continues, prefer adding an exo/head diagnostic to analysis
   only; do not feed `exo_camera_1` into this checkpoint without retraining or
   explicit evidence that the model supports it.
