# Molmo vs Pi 모델 비교: 자체 데이터 학습

> **날짜:** 2026-04-07
> **배경:** 자체 로봇 시뮬레이션 데이터 + 소량의 실제 로봇 데이터로 VLA 모델 학습 시, Pi에서 Molmo로의 전환 여부 평가
> **면책:** 본 문서는 문헌 조사 결과이며 스택 선택을 위한 최종 추천이 아닙니다. 보고된 성능 수치는 서로 다른 논문/로봇/태스크에서 측정된 것으로 직접 비교가 불가능하며, 자체 로봇에서의 파일럿 실험이 최종 결정의 근거가 되어야 합니다.

---

## 1. 요약

| | Molmo (AI2) | Pi (Physical Intelligence) |
|---|---|---|
| **핵심 강점** | 완전 오픈소스, 시뮬 데이터 파이프라인, 고해상도 비전 | 소량 실제 데이터 fine-tune 효율, 낮은 컴퓨팅 비용 |
| **핵심 약점** | 높은 컴퓨팅 비용 (4-32x H100), 생태계 분산 | 224x224 고정 해상도, 최고 모델/데이터 비공개 |
| **가장 적합한 시나리오** | 시뮬 데이터 중심 학습 | 소량 실제 데이터 중심 학습 |

## 2. 아키텍처 비교

### 2.1 Molmo 생태계

**Molmo2 (2025년 1월)** — VLM 기반:

| 모델 | LLM 백본 | 파라미터 |
|------|----------|---------|
| Molmo2-4B | Qwen3-4B-Instruct | ~4B |
| Molmo2-8B | Qwen3-8B | ~8B |
| Molmo2-O-7B | OLMo-3-7B-Instruct | ~7B (완전 오픈) |

- **비전 인코더:** CLIP ViT-L/14 (고해상도 지원)
- **기능:** 밀집 캡셔닝, 포인팅/그라운딩, 공간 추론, 비디오 이해 (최대 384프레임)

**MolmoAct (2025)** — 7B VLA:
- 3단계: 깊이 인식 퍼셉션 → 궤적 트레이스 → 저수준 액션
- SimplerEnv 70.5% 제로샷, LIBERO 86.6%

**MolmoBot (2026년 3월)** — Sim-to-Real:
- Molmo2-4B + Flow Matching ActionExpert (32블록)
- 170만 순수 시뮬 에피소드 (MuJoCo)
- Franka FR3, Rainbow Robotics RB-Y1에서 테스트

### 2.2 Pi 생태계

**Pi-0 (2024년 10월)** — 기반 VLA (3.3B):
- PaliGemma 3B + Action Expert 300M
- **224x224 고정 해상도**, Flow Matching, 최대 50Hz

**Pi-0-FAST** — DCT + BPE 토큰화. 학습 5배 빠름, 추론은 느림.

**Pi-0.5 (2025년 4월)** — Knowledge Insulation, 다단계 행동 (10-15분).

**Pi-0.6\* (2025년 11월)** — Gemma 3 4B, 860M Action Expert, 90%+ 성능. **비공개.**

## 3. 오픈소스 완전성

| 자산 | Molmo | Pi |
|------|-------|----|
| 모델 가중치 | 전 변형 (4B–72B) | Pi-0, Pi-0-FAST, Pi-0.5만 |
| 최고 모델 공개? | 예 | **아니오** (Pi-0.6\* 비공개) |
| 학습 코드 | 전체 (pre-train, SFT, LoRA) | JAX + PyTorch (OpenPI) |
| 학습 데이터 | **100% 공개** | **90.9% 비공개** |
| 시뮬 파이프라인 | MolmoSpaces + MolmoBot-Engine | **없음** |
| 라이선스 | Apache 2.0 | Apache 2.0 (OpenPI) |

## 4. 파인튜닝 비교

### 4.1 하드웨어 요구사항

| 방법 | Molmo | Pi | 출처 |
|------|-------|----|------|
| 추론 | 단일 GPU (4B) | >8GB VRAM | 각 README |
| LoRA fine-tune | 4-8x A100 (PoC) ~ 32x H100 (재현) | 단일 A100 (>22.5GB) | 출처별 상이 |
| Full 학습 | 8-64x H100 | >70GB | 논문 기준 |

### 4.2 데이터 파이프라인

- **Molmo:** HDF5 궤적 + HuggingFace 통합 + 정규화/검증 도구
- **Pi:** LeRobot 포맷 + OpenPI 변환 유틸리티 + DROID/ALOHA/UR5 기본 설정

### 4.3 소량 실제 데이터 파인튜닝

**Pi가 설계상 유리:** "대규모 pre-train → 1-20시간 task-specific fine-tune" 패러다임. 7개 로봇, 68개 태스크에서 검증.

**Molmo:** 제로샷 sim-to-real에 초점. 시뮬+실제 하이브리드 파이프라인 문서가 부족.

## 5. 보고된 성능

### 5.1 MolmoBot vs Pi-0.5 (동일 하드웨어 Franka FR3, MolmoBot 논문)

| 태스크 | MolmoBot | Pi-0.5 |
|--------|----------|--------|
| Pick-and-place | 79.2% | 39.2% |

### 5.2 MolmoAct vs Pi-0-FAST (MolmoAct 논문, 독립 검증 필요)

| 태스크 | MolmoAct vs Pi-0-FAST |
|--------|-----------------------|
| 단일 팔 | +10% |
| 양팔 | +22.7% |
| OOD 일반화 | +23.3% |

> 5.1과 5.2는 다른 모델 쌍, 다른 베이스라인, 다른 태스크입니다. 통합 불가.

### 5.3 Pi-0 독립 평가 (UPenn, 300+ 시행)

전체 성공률 ~24%. 세밀한 조작 실패, 공간 추론 부족, 224x224 병목 확인.
Pi-0.6\*와는 다른 모델임에 유의.

### 5.4 플랫폼 커버리지

- **Molmo:** 2개 (Franka FR3, RB-Y1)
- **Pi:** 7개 (UR5e, Franka, ALOHA 등)

## 6. 시나리오별 분석

### Pi가 유리할 수 있는 조건
- 실제 데이터 1-20시간, 빠른 반복 필요
- GPU 제한 (단일 A100)
- Pi 코드에 기존 투자 있음
- 타겟 로봇이 OpenPI에 이미 지원됨

### Molmo가 유리할 수 있는 조건
- 시뮬 데이터가 주요 학습 소스
- 고해상도 비전이 중요
- 파이프라인 투명성/디버깅 필요
- 시뮬 데이터를 장기 확장 계획

### 하이브리드 (Molmo VLM + Pi 스타일 Action Head)
MolmoBot 레포에 `MolmoBot-Pi0` 변형이 존재하나, 자유로운 구성 요소 조합이 아닌 특정 설정. 통합 경로는 검증되지 않았으며, 데이터 포맷/학습 파이프라인 호환성 확인이 필요.

## 7. 주요 리스크

### Pi
- 224x224 고정 — 아키텍처 제약, 파인튜닝으로 해결 불가
- 최고 모델(0.6\*) + 90.9% 데이터 비공개
- 시뮬 파이프라인 없음
- 독립 평가 ~24% 성공률

### Molmo
- 높은 컴퓨팅 비용 (4-32x H100)
- 생태계가 5+개 레포에 분산
- Allen AI 장기 유지보수 의존
- 깊이 센서 네이티브 미지원
- 액션 256빈 이산화 한계

## 8. 다음 단계

### 확인된 사실 vs 미확인 가설

| 주장 | 상태 |
|------|------|
| Molmo: 시뮬 파이프라인 보유, 전체 오픈소스, 고해상도 | **확인됨** |
| Pi: 소량 데이터 fine-tune 설계, 낮은 컴퓨팅 비용, 7개 로봇 검증 | **확인됨** |
| Pi: 224x224 고정, 최고 모델 비공개, 90.9% 데이터 비공개 | **확인됨** |
| Molmo가 Pi보다 성능 우수 | **미확인** — 서로 다른 논문/로봇/태스크 교차 비교 |
| 어느 쪽이든 우리 로봇에서 작동 | **미확인** — 파일럿 필요 |

### 추천: 탐색적 파일럿

스택 선택 전에 소규모 탐색적 파일럿을 수행합니다. 논문 수준의 통계적 엄밀성이 아닌, 방향성 확인이 목적입니다.

1. **양쪽 모델을 우리 로봇 시뮬에서 실행** — 작동 여부 + 대략적 성능 확인
2. **가능하면 실제 로봇에서도 소규모 테스트** — sim-to-real 갭 감각 확보
3. **결과에 따라 결정** — 한쪽이 명확히 우세하면 채택, 비슷하면 컴퓨팅 비용/생태계로 판단

시뮬에서만 좋은 결과가 나와도 실제 로봇 검증 없이 최종 결정하지 않습니다.
